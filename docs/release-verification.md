Историческая проверка ранней сборки. Актуальная версия и проверки:
[VK Player 0.3.0](release-0.3.0-verification.md).

Артефакт: `release-tauri/VK Player_0.1.0_x64-setup.exe`, 2 201 888 байт.
SHA-256: `82f5dfa81d7c201d2b71c459f01d244e95c04384e548f1690c37e787cc8890ce`.

Tauri 2, React, Rust, системный WebView2. Новая иконка используется в установщике,
окне, трее и интерфейсе. Release-сборка выполнена через `npm run dist`.

Проверки текущих исходников:

- TypeScript и production renderer: PASS.
- Rust: 23/23, форматирование: PASS.
- Vitest: 2/2.

Нативные проверки использовали отдельный временный профиль и настоящие WAV-файлы.
Подтверждены воспроизведение, range requests, изоляция неимпортированных файлов,
перезапуск, закрытие Windows сразу после создания плейлиста, защита от устаревшего
сохранения после импорта/удаления. Найденное зависание создания официального окна
VK исправлено переводом команды в async и перепроверено. Тесты VK используют
контролируемые ответы; они подтверждают поведение клиента, а не доступ VK.

## Что остаётся непроверенным

В `src-tauri/vk-config.json` нет зарегистрированного client ID. Вход через VK ID,
музыкальные разрешения, фактические схемы ограниченного audio API и операции
реального аккаунта не подтверждены. Прямая загрузка локальных файлов в VK не
реализована. Отдельное официальное окно VK доступно без client ID; оно не
синхронизирует данные с собственным интерфейсом Pulse.

Нельзя считать пользовательское требование полной VK-синхронизации закрытым до
выдачи прав приложению и сопоставления реальной библиотеки/плейлистов с VK, включая
проверку операций записи и последующее чтение. Подробные источники ограничений:
`vk-access-evidence.md`.
