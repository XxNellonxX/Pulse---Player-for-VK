# Pulse 0.5.0-preview.5 — файловые загрузки VK

Локальная проверочная сборка. Публикация приостановлена по просьбе пользователя:
предыдущий draft preview.4 не опубликован, новые изменения не отправлены в GitHub.

## Исправленные причины

- Для старых записей без подтверждённой карточки исполнителя поиск SoundCloud
  выполняется до команды воспроизведения VK, если включено предпочтение SoundCloud.
  Отсутствие карточки не объявляется доказательством происхождения записи.
- Курсор следующей страницы SoundCloud больше не запрещает единственное строгое
  совпадение среди полученных результатов. Конкурирующие точные записи требуют
  выбора пользователя. Автоматическая связь остаётся предложением по метаданным,
  а не доказательством идентичности аудиофайлов во всём каталоге.
- Сопоставление учитывает явные разделители совместных исполнителей и публикации
  вида `TRACK PREMIERE: исполнители - название`, сохраняя исходную атрибуцию.
  Также читается `publisher_metadata.artist`. Другая версия, длительность,
  противоречащий ISRC или цензурная редакция не подменяются молча.
- Отказ команды запуска VK теперь запускает резервный поиск. Два сообщения об
  ошибке VK подряд не отменяют переход на SoundCloud. Поздние ответы старого
  источника отклоняются до следующего React-render.
- Повторный выбор того же трека после ошибки начинает новую попытку. Неудачный
  поиск сообщает о необходимости выбрать источник, вместо повторного запуска
  уже отказавшего VK с бесконечным ожиданием.
- Поиск декодера предоставленных VK URL учитывает методы прототипа и Babel,
  ограничен четырьмя уровнями и не вызывает геттеры. Проверяется до трёх
  источников одновременно с интервалом 1,5 секунды. Их полное время загрузки
  сохраняется; четвёртый источник при трёх зависших может ждать до 25 секунд.
- Полная нативная проверка обнаружила отдельный дефект: Tauri `convertFileSrc`
  кодировал весь `token/0` как один компонент (`token%2F0`). Обработчик аудио
  ожидал два компонента и отвечал 404 при успешных поиске, привязке и выдаче потока.
  Формирование URL и получение ID для освобождения сессии исправлены совместно:
  преобразуется только токен, затем добавляется буквальный `/0`.
- После устранения 404 нативная проверка обнаружила второй дефект. Wry передаёт
  Rust-обработчику внутренний `pulse-media://localhost`, а браузер Windows
  обращается по HTTP/HTTPS. Реконструкция внутреннего адреса попадала в HLS
  и приводила к `net::ERR_FAILED` для частей трека. Теперь HLS содержит только
  относительные числовые индексы, которые сохраняют исходный протокол браузера
  и ту же приватную сессию. Проверки аккаунта, поколения и источников сохранены.

## Проверки 23 октября 2026

- TypeScript и production frontend build: успешно.
- Vitest: **125/125**, включая отрицательный контроль с настоящим upstream
  Tauri 2.12.4 `core.js` для Windows HTTP/HTTPS и macOS.
- Node-регрессии `qa/*.node.mjs`: **302/302**.
- Rust: основной прогон **169 успешно, 5 ignored**; затем добавленные независимые
  проверки вложенных HLS **3/3**. Пропущенные проверки требуют внешних
  сервисов или отдельно упакованных нативных инструментов; это не runtime pass.
- Независимые проверки реального React-хука в чистом Edge: **20/20** новых
  сценариев, включая старую библиотеку, отказы, повторы, отмену и поздние ответы.
  Метаданные, сеть и медиачасы в этом наборе подставные.
- Существующие независимые сценарии SoundCloud/fallback реального React-хука:
  **41/41** после окончательных изменений.
- Независимые проверки транспортного планировщика: **6/6**, включая 16
  неотвечающих источников, 30 замен, одновременную готовность и очистку ресурсов.
- Отдельные проверки настоящего HTMLAudio/AAC/HLS в Edge: **10 сценариев**.
- Независимый тест настоящего `desktop.ts` с реальными Tauri invoke/converter
  и подставным Rust IPC: **15/15 групп** для Windows HTTP/HTTPS и схемы macOS,
  включая точное освобождение сессии и отклонение некорректных URL.
- Независимые Rust-сценарии проверяют вложенный master/media HLS, повторные
  AES-ключи, карты, byte ranges, rendition/preload URI, три платформенных адреса,
  отзыв регистрации и заполненный реестр ресурсов. Выполняются настоящий
  rewriter и registry; нативный runtime и физический Mac ими не подменяются.

## Платформы и данные

Финальные Windows production EXE и установщик **0.5.0-preview.5** успешно
пересобраны после обоих исправлений медиапротокола.
Файл: `release-tauri/VK Player_0.5.0-preview.5_x64-setup.exe`,
размер **107747472 байта**, SHA256:
`de451aea0ee7d9f53f6e2b06b54aaab1cfb8c5fd19e03053bcdf0ad57bf5e8c5`.
Production EXE содержит публичный gateway; отладочных маркеров QA-профиля
и QA-файла нет. Проверка 28 файлов-кандидатов на два известных приватных
значения не обнаружила совпадений. `git diff --check` прошёл.
Установщик поверх работающего пользовательского плеера не запускался.

Изменения находятся в общих `src/` и `src-tauri/`. Идентификатор приложения
`ru.vkplayer.desktop`, профиль, настройки и библиотека сохранены.
Тесты с подставным аккаунтом используют отдельный QA identifier и временный профиль.

Новая сборка macOS arm64/x64 и вход/воспроизведение на физическом Mac в этом
проходе не проверены. Успешные macOS-сборки предыдущего preview.4 не относятся
к этому изменению. Android не реализован. Общий stable Release не публикуется.

Постоянная доступность любой записи стороннего каталога не подтверждена.
Если точного источника нет, требуется выбор записи или собственный исходный файл.
Кеш SoundCloud остаётся ограниченным сроком сессии; постоянный архив не создаётся.
