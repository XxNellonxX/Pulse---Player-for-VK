23 октября 2026 года. Версия 0.5.1 опубликована в
[GitHub Release v0.5.1](https://github.com/XxNellonxX/Pulse---Player-for-VK/releases/tag/v0.5.1), ID `422002954`, `draft=false`,
`prerelease=false`; `/releases/latest` возвращает этот же выпуск. Windows EXE
и оба macOS DMG собраны из исходной ревизии `656e9652aa22a2722532451491b13d04cac3178b`, закреплённой тегом

## Описание для GitHub Release

Pulse 0.5.1 объединяет исправления воспроизведения и новые возможности коллекции,
которые появились после стабильной версии 0.4.1.

- Улучшен запуск загруженных в VK файлов: медленный исходный поток не
  прерывается только из-за ожидания другого источника. Собственный файл,
  загруженный через Pulse с подтверждённым сохранением в VK, сохраняется локально
  для повторного воспроизведения. Для старой записи можно вручную выбрать свой
  оригинальный файл.
- Добавлен независимый источник SoundCloud, автоматический подбор по
  исполнителям, названию, версии и длительности и ручной выбор неоднозначной
  записи. Ограничение песни в VK само по себе не блокирует доступную запись
  SoundCloud. Исправлены адреса приватного HLS-потока, из-за которых успешный
  поиск мог заканчиваться ошибкой запуска.
- Встроен маршрут Pulse Gateway для SoundCloud и каталога артистов. Слушателю
  не нужны API-ключи или настройка системного прокси; VK использует прямое
  соединение. Ограниченный кеш сегментов ускоряет повторное воспроизведение и
  перемотку в пределах действующего сеанса. Восстановление ограничено по времени
  и числу попыток, сохраняет позицию и не меняет маршрут следующих песен.
- Добавлен перенос коллекций CSV/TSV/JSON и доступных публичных плейлистов
  Spotify / Яндекс Музыки. Порядок и повторные записи сохраняются; можно
  продолжить подбор, проверить неоднозначные совпадения и отдельно сохранить
  найденное в VK. В «Моей музыке» появились порядки из Spotify и Яндекс Музыки;
  порядок «Как в VK» остаётся порядком VK.
- В карточке исполнителя появилась кнопка «Все треки» с отдельной постраничной
  загрузкой полного доступного каталога. Поиск других песен больше не делает
  ранее показанные записи недоступными из-за вытеснения их метаданных.
- Добавлены поиск артистов и релизов через MusicBrainz, подписки и локальная
  лента обнаруженных релизов с фоновым обновлением и кешем. Каталог с датой
  релиза не выдаётся за подтверждённый анонс исполнителя.
- В разделе «Миксы» доступны рекомендации аккаунта VK и отдельный Pulse Mix,
  учитывающий историю выбранных песен, разнообразие артистов и новые находки.
  Запуск песни не перестраивает уже показанный микс. Это отдельная подборка,
  а не официальный поток VK Mix.
- Добавлены темы «Y2K / 90-е» и «Стекло», всего 17 палитр. «Стекло» создаёт
  полупрозрачные слои внутри окна. Альбомный стиль удалён, сохранённая настройка
  переводится в минимальный стиль.
- Нажатие на динамик выключает звук и возвращает прежнюю громкость. Перемотка
  слегка увеличивается при взаимодействии без прямоугольной рамки; фокус
  клавиатуры отмечается на круглом бегунке.
- Меню сортировки следует выбранной теме, выделяет текущий порядок и поддерживает
  управление мышью и клавиатурой. Порядки VK / Spotify / Яндекса и сортировка
  по названию / исполнителю сохранены; алгоритм сортировки не менялся.

### Что важно знать об импорте

Личный вход Spotify **не включён**: в сборке пока нет зарегистрированного и
допущенного Spotify Client ID. Пользователю не предлагается регистрировать
приложение или вводить технические ключи. Доступны файлы экспорта и публичные
ссылки, когда сервис разрешает их чтение. В текущем регионе публичный Spotify
embed возвращал 451; Pulse показывает отказ, а не пустой успешный импорт.

Вход Яндекс Музыки реализован через отдельное официальное окно без извлечения
паролей, cookies или токенов. Публичная коллекция проверена, но перенос личной
коллекции с реальным авторизованным аккаунтом пока не подтверждён. Изменение
сайта Яндекса может потребовать адаптации.

Перенос коллекции получает названия, исполнителей и порядок, а полную доступную
запись подбирает отдельно. Он не скачивает защищённое аудио Spotify / Яндекса.
Совпадение метаданных не доказывает идентичность аудиофайлов. Разные версии и
неоднозначные совпадения требуют выбора. Сетевой отказ оставляет возможность
повторить поиск и не объявляет песню отсутствующей.

### Обновление и платформы

Windows: завершите Pulse и запустите установщик поверх прежней версии. Приложение
сохраняет идентификатор `ru.vkplayer.desktop` и прежние расположения профиля,
библиотеки и настроек. Сессия VK остаётся действительной, пока её принимает VK.
Установка поверх личного профиля в автоматических проверках не выполнялась.

Windows 10/11 и macOS 14+ используют общий frontend и Rust backend. Пакеты
Windows, Apple Silicon и Intel должны иметь одну версию и ревизию исходников.
macOS-пакеты пока **не подписаны и не notarized Apple**; это preview для Mac.
На физическом Mac вход, аудио, личные импорты, Keychain и обновление ещё не
проверены. Android пока не реализован.

Доступность каждой песни, внешнего сервиса или конкретного сетевого маршрута
не гарантируется. Кеш SoundCloud ограничен сеансом и не является постоянным
офлайн-архивом; собственные сохранённые MP3 хранятся отдельно на диске.

## Проверки исходного кода и Windows QA 0.5.1

- Меню сортировки: TypeScript и 11 Edge-проверок прошли; скриншоты
  проверены. Использованы отдельный чистый браузер и синтетические данные.
- Сравнение версий: 6 Rust-тестов прошли. Прежний парсер принимал только x.y.z
  и отвергал установленную preview-версию, поэтому успешный `/releases/latest`

## Проверки воспроизведения, унаследованные от preview.6

[Отчёт preview.6](release-0.5.0-preview.6-verification.md) фиксирует реальный
SoundCloud/VPS и нативный декодер в отдельном Windows QA-приложении с подставной
библиотекой VK: 5/5 запусков с перемоткой, 75 ответов медиа HTTP 200, без ошибок
renderer. Первые три секунды медиачасов достигались примерно за 4,3–4,9 секунды.
Это не замер текущей версии 0.5.1 и не обещание такой задержки в любой сети.

Полные проигрывания двух песен до `ended` были выполнены в промежуточной
QA-сборке preview.6; окончательная сборка проверялась запуском и перемоткой.
Повтор HLS восстановил отдельно внедрённый отказ manifest 503, но в этой
проверке не был вызван ожидавшийся обработчик повторного resolve приложения;
недостаток покрытия сохранён в исходном отчёте. Все эти прогоны были приглушены
и не измеряют слышимые микропрерывания на физическом аудиовыходе.

Массовый аудит первых 800 записей проверял метаданные и ограниченный поиск
SoundCloud. Он не проигрывал всю библиотеку и не доказывает доступность всех
песен. В preview.7 аудиотранспорт не изменялся; новые независимые регрессии
прошли, но не заменяют проверку реальных провайдеров и физического Mac.

### Сопутствующие документы и процедура публикации

README и `docs/macos-release.md` содержат опубликованные ссылки 0.5.1.
Исторические 0.4.1 / preview.6 сохранены отдельно. Описание аудио по URL не
приравнивается к новому импорту метаданных коллекций: отсутствие полного
Spotify-файла по ссылке не запрещает перенос CSV/JSON.

Workflow `publish-macos-preview.yml` в ревизии 0.5.1 поддерживает перенос в
существующий черновик stable или prerelease. Он проверяет тип выпуска по тегу,
успешное завершение исходной macOS-сборки, совпадение source SHA, наличие обеих
архитектур и имена пакетов; загружает DMG и контрольные суммы, но не публикует
сам выпуск. Сборочный `release-macos.yml` сохраняет обе архитектуры в
CI-артефактах. Выполнение переноса и отдельная публикация 0.5.1 подтверждены выше.

Неподписанные Mac-файлы сохраняют явную пометку preview рядом со стабильным
Windows-пакетом. Полный стабильный статус Mac требует физических проверок,
подписи и notarization; успешный CI их не заменяет.
