# Импорт коллекций Spotify и Яндекс Музыки

Импорт переносит метаданные любимых треков и плейлистов. Порядок и повторные записи сохраняются. Полные записи подбираются существующим механизмом Pulse отдельно; превью, DRM-потоки и чужие похожие версии не выдаются за импортированный оригинал. Исходные позиции доступны и у списка с пропусками.

## Spotify: настройка владельцем приложения

1. Создайте приложение в [Spotify Developer Dashboard](https://developer.spotify.com/dashboard).
2. Разрешите Web API и зарегистрируйте **точно** `http://127.0.0.1:43823/pulse-spotify` как Redirect URI.
3. В Development Mode у владельца приложения должна быть активна Spotify Premium; в User Management разрешаются до 5 пользователей. Обычный вход без allowlist может завершиться успешно, но API затем вернёт 403. Client ID сам по себе не снимает эти ограничения.
4. Владелец Pulse задаёт публичный Client ID переменной сборки `PULSE_SPOTIFY_CLIENT_ID`. Пользователю не нужно регистрировать приложение или вводить технические ключи. Пока сборка не настроена, личный вход Spotify недоступен; остаются экспорт CSV/JSON и доступные публичные ссылки.
5. В настроенной сборке пользователь нажимает «Подключить Spotify» и разрешает чтение коллекции в системном браузере. Его аккаунт должен иметь фактический доступ к приложению на стороне Spotify.

**Client Secret не нужен и не должен попадать в клиентское приложение.** Применяется Authorization Code + PKCE S256, случайные verifier/state, фиксированный loopback callback с проверкой Host/path/state. Токены не передаются renderer и хранятся в Windows Credential Manager / macOS Keychain. Обновление access token использует refresh token. Отключение аккаунта удаляет локальные учётные данные.

Запрашиваются только `user-library-read`, `playlist-read-private`, `playlist-read-collaborative`. «Любимые треки» читаются через `/me/tracks`, список плейлистов — через `/me/playlists`. Для новых Development Mode приложений состав плейлиста читается через `/playlists/{id}/items` и доступен только владельцу или соавтору; присутствие чужого плейлиста в списке подписок не даёт право прочитать его состав. Для совместимости с прежними/Extended приложениями допускается один повтор через `/tracks` только при HTTP 404/410 у `/items`, без повторов на 401/403/429. Поддерживаются старые поля `track` и новые `item`, скрытые null-записи сохраняют пропуск в исходной позиции. Чтение идёт страницами по 50 записей; верхняя граница одной коллекции — 20 000 записей / 400 страниц. Перед и после чтения плейлиста проверяется snapshot. Частичная выдача, изменение состава, скрытые файлы и отказ сервиса отображаются явно. Rate-limit не вызывает бесконечных повторов.

Публичный URL работает без входа, когда Spotify предоставляет embed-метаданные в текущем регионе. Embed нередко показывает только часть плейлиста; Pulse не обозначает такой список полным без доказанного количества. В текущей проверке публичный Spotify embed вернул внутренний статус 451 «not available in your country»; это обработано как отказ, а не пустой успешный импорт. Реальный личный OAuth-вход требует зарегистрированного Client ID и проверки авторизованным пользователем.

На 23 октября 2026 года Spotify разрешает до 25 Client ID на разработчика; лимит пользователей Development Mode остаётся 5 на приложение. Публичный вход для неограниченного круга пользователей требует Extended Quota. Spotify принимает новые заявки на него только от организаций с действующим сервисом и как минимум 250 000 активных пользователей в месяц. Поэтому подготовленный PKCE-код не означает доступного всем личного импорта: нужен зарегистрированный и допущенный Spotify клиент. Официально документированного способа заменить эту регистрацию встроенным окном веб-плеера нет.

## Яндекс Музыка

Публичные плейлисты вида `https://music.yandex.ru/users/…/playlists/…` читаются как метаданные, без пароля и токена. Фиксированный API-origin, страницы по 100 записей, проверка revision/count/page, верхняя граница 20 000 записей / 400 страниц. Отказ, повторенная страница и неполный список видимы пользователю. Короткий URL нужно открыть и скопировать полную ссылку; закрытые коллекции не считаются публично доступными.

Реальная проверка публичного списка `yamusic-top/1028` получила HTTP 200, 100 объявленных и 100 фактически предоставленных записей. Отдельный запрос `page=1&page-size=20` подтвердил реальную пагинацию: page 1, perPage 20, 20 записей. Это не подтверждает личную авторизованную коллекцию или проигрывание всех записей.

Личный вход использует отдельное окно Яндекс Музыки и доступ страницы к данным вошедшего пользователя. Пароли вводятся на официальной странице, cookies и токены не копируются в Pulse. Возможность прочитать всю коллекцию зависит от фактической выдачи сервиса; работа на физическом Mac и реальном авторизованном аккаунте отдельно проверяется и не следует из успешной сборки.

## Файл полного экспорта

CSV / TSV с заголовками `Track Name, Artist Name(s), Album Name, Duration (ms), ISRC, Explicit` либо `title, artists, album, duration` (секунды). Поддерживаются запятая, `;`, табуляция, кавычки RFC 4180, переносы строк внутри кавычек и UTF-8 BOM. Несколько артистов в одной ячейке разделяются `;`; запятые внутри имён артистов не разрезаются.

JSON: массив записей либо `{ "title": "Название", "tracks": [...] }`, запись `{ "id": "...", "title": "...", "artists": ["..."], "album": "...", "duration": 180 }`. Вместо duration допустим durationMs. Необязательные isrc и explicit сохраняются; аудио URL и любые случайные поля экспорта отбрасываются.

Ограничения: 8 МБ метаданных, до 20 000 записей за один импорт. Повторные треки не удаляются. Записи без названия/исполнителя пропускаются с исходной позицией и предупреждением; такой импорт обозначается частичным.
