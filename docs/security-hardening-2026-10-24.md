# Усиление безопасности Pulse — 24 октября 2026

Подготовлено для общей версии 0.5.2 Windows/macOS. Проверки ниже относятся к
исходникам и указанным запускам; они не являются обещанием полной неуязвимости.

## Нативные команды и официальные окна входа

В `src-tauri/src/desktop_security.rs` добавлена проверка перед обработкой
собственных команд приложения. Разрешено только окно `main` с WebView `main`
и origin встроенного Pulse: `tauri://localhost`, `http://tauri.localhost` или
`https://tauri.localhost` с обычным портом. URL с userinfo, внешние сайты,
asset/audio-протоколы и вспомогательные окна не получают нативные команды.
В dev-режиме допускается только точно заданный origin `build.devUrl`; в
релизной сборке исключения для произвольных loopback-сайтов нет.

Это дополнительный слой поверх Tauri ACL и CSP. Capability для событий по-прежнему
ограничена `main`; разрешение native IPC для удалённых сайтов не добавлялось.
Проверки покрывают штатные Windows/macOS origin, похожие имена доменов, другие
порты, asset/audio/file URL, userinfo и вспомогательные окна после локальной
навигации.

Навигация в официальных окнах VK ограничена HTTPS на порту 443 без userinfo и
доменами VK с проверкой границ имени. Окна VK/Яндекс сохраняют собственные
профили и ограничения навигации. Независимая проверка исходников подтвердила:
их ответы возвращаются через нативный `WebviewWindow::eval_with_callback` →
runtime dispatcher Tauri 2.12.4, а не через пользовательский `invoke_handler`.
Новый main-only guard эти callbacks не перехватывает. Spotify использует
отдельный проверяемый loopback OAuth callback. Проверка исходников не заменяет
реальный вход в аккаунты: подписанные сессии сервисов этим набором не проверялись.

## Автозапуск

Однократная настройка сохраняет marker в профиле **до** попытки регистрации в ОС:
сбой или повторный запуск не вызывают бесконечные попытки включения. Ранее заданное
отключение в системных настройках сохраняется. На Windows используется запись
текущего пользователя HKCU Run с полным путём EXE в кавычках; административные
права и изменение машинного автозапуска не требуются. Dev/QA и вспомогательные
идентификаторы приложения не регистрируют автозапуск.

На macOS используется официальный `SMAppService`; система может требовать
подтверждение и корректную подпись приложения. Поэтому unsigned preview может
получить отказ регистрации, который следует показать пользователю. Реального
Mac для подтверждения этого сценария нет.

Есть известное ограничение Windows: после удаления приложения запись HKCU Run
может остаться. До удаления следует выключить автозапуск в Pulse или системных
настройках. Installer hook для очистки не добавлен, поскольку запуск удаления
старой версии при обычном обновлении мог бы ошибочно убрать автозапуск новой.
Шесть focused Rust-проверок и независимая UX-проверка **12/12** прошли; окончательный
native-прогон свежей сборки ещё ожидается.

## Зависимости

- Удалена неиспользуемая прямая зависимость `zod`. Поддерживаемый desktop работает
  на Tauri; сохранённая legacy-сборка Electron обновлена до 44.9.3. После изменений
  полный `npm audit` и `npm audit --omit=dev` сообщили **0 известных уязвимостей**.
  Это состояние базы advisory на момент проверки, а не гарантия отсутствия
  неизвестных проблем.
- В Cargo.lock обновлены `rustls-webpki` до **0.103.16** по
  [RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382.html) и
  `tokio` до **1.54.1** по
  [RUSTSEC-2026-0384](https://rustsec.org/advisories/RUSTSEC-2026-0384.html).
- В этой среде `cargo-audit` недоступен. Вместо него выполнена OSV batch-проверка
  **541 registry-пакета** из финального lockfile, включая новые зависимости
  автозапуска, и анализ дерева зависимостей по целям.
  OSV-проверка не равнозначна полному аудиту исходников каждой зависимости.

В общем lockfile остаются advisory, которые нельзя скрывать под формулировкой
«Rust полностью чистый»:

| Пакет | Версия в lockfile | Advisory / состояние |
|---|---|---|
| `glib` | 0.18.5 | RUSTSEC-2024-0429 / GHSA-wrw7-89jp-8q8g; ветка Linux GTK, отсутствует в проверенных деревьях Windows/macOS |
| `paste` | 1.0.15 | RUSTSEC-2024-0436, пакет не поддерживается |
| `proc-macro-error` | 1.0.4 | RUSTSEC-2024-0370, пакет не поддерживается |
| `zbus_names` | 4.3.5 | RUSTSEC-2026-0371, пакет не поддерживается |
| `zvariant` | 5.15.1 | RUSTSEC-2026-0370, пакет не поддерживается |
| `zvariant_derive` | 5.15.1 | RUSTSEC-2026-0372, пакет не поддерживается |

Отсутствие Linux GTK в текущих desktop-целях не устраняет advisory из lockfile.
Если будет добавлена Linux-сборка, этот риск нужно разобрать до её публикации.
Предупреждения о сопровождении требуют наблюдения за upstream и обновления
родительских зависимостей; наличие advisory само по себе не устанавливает
эксплуатируемость в Pulse.

## Проверка серверного gateway

Проверены исходники собственного `services/pulse-gateway`, входные HTTP-маршруты,
исходящий транспорт, SSRF/DNS-проверки, OAuth, media capabilities, кеши, квоты,
логирование и конфигурация Caddy/Docker. Проверки gateway выполнялись локально с
фиктивными ответами провайдеров. Реальные ключи и библиотека пользователя в этих
проверках не использовались. Затем обновление gateway развёрнуто на собственном
VPS с отдельными проверками, описанными ниже.

### Исправления gateway

- CORS сам по себе не препятствовал слепым браузерным GET-запросам, расходующим
  общую квоту провайдеров. Чужой `Origin` и чужой контекст `Sec-Fetch-Site` теперь
  отклоняются до работы с провайдерами. Нативный клиент 0.5.1 не отправляет эти
  заголовки; формат запросов, ответов и авторизация клиента не изменены.
- Временные IPv6-адреса одного `/64` больше не получают отдельную квоту.
  Эквивалентные IPv6-записи и IPv4-mapped адреса нормализуются. При этом доступ
  к media capability остаётся привязан к точному IP, а не ко всей подсети.
- На health, JSON, media и ошибках заданы `Referrer-Policy: no-referrer`,
  `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY` и CSP, запрещающая
  активное содержимое и встраивание. Media bytes и MIME не изменяются.
- Внешний HTTPS-listener Caddy получил конечные сроки ожидания заголовков,
  тела запроса, записи ответа и idle-соединения, а также предел 16 000 байт
  заголовков. Политика отсутствия access/error URI-логов сохранена.

### Проверено локально

`npm run test:gateway` на Node 24.21.0 с явно указанным локальным Caddy 2.11.7
через `CADDY_BINARY`: **78 прошли, 0 ошибок, 0 пропусков**. Новый набор
`qa/gateway-hardening-independent.test.mjs` поднимает настоящий HTTP-handler на
loopback с фиктивным upstream и проверяет отказ чужому браузерному контексту,
сохранение квоты для нативного клиента, headers/HEAD/media bytes, IPv6-квоту,
точную IP-привязку и доверие forwarding-заголовкам только на loopback.

Существующие тесты также прошли: SSRF allowlist, запрет служебных IPv4/IPv6,
DNS pinning, ограничения ответа и времени, редиректы и отсутствие OAuth на CDN,
корректность диапазонов, срок/вытеснение capability, отсутствие кеширования
ключей и manifest, границы RAM-кеша и квот. Реальный локальный Caddy проверен
на недоступном фиктивном upstream без утечки media URI. Opaque HLS прошёл
локальное декодирование и seek через существующий QA adapter.

### Пределы серверной проверки

Это аудит исходников и локальные регрессионные проверки, а не гарантия отсутствия
всех уязвимостей и не нагрузочное тестирование публичной инфраструктуры. Заголовки
браузерного контекста не заменяют авторизацию: отдельная программа может обращаться
к публичному gateway. Несколько независимых IP могут расходовать общую квоту
SoundCloud, трафик и глобальные лимиты. Один VPS остаётся точкой отказа; необходимы
лимиты/алерты и DDoS-защита хостера, обновление ОС/Node/Caddy, ограничение SSH и
защита аккаунтов хостинга/GitHub. Digest образов Docker в комплекте пока не
закреплены; перед обновлением production нужно выбрать и проверить конкретные
образы. Root/Docker-администратор VPS способен прочитать серверное окружение.

### Развёртывание и штатная проверка VPS

SSH с проверкой ранее закреплённого host key восстановился после первоначального
timeout до banner. Штатная проверка показала Ubuntu 24.04.5, Docker 29.1.3 и
loopback-привязку порта приложения. На сервер перенесён только явный allowlist
исходников gateway; перед изменением сохранены приватная резервная копия
исходников/окружения и прежний image с отдельным tag для rollback. Секреты `.env`
и Caddy volumes сохранены; их содержимое не публикуется.

До переключения кандидат прошёл **37/37 unit-тестов внутри Docker с
`network=none`** и проверку конфигурации Caddy. После пересоздания контейнера
gateway получил healthy, Caddy оставался running, внешний HTTPS health вернул
**200**. Это штатное обновление собственного сервера, без атак или сканирования
чужой инфраструктуры.

Два обычных SoundCloud probe прошли поиск, получение HLS manifest и первого
media-ресурса за **1403 мс** и **1042 мс**. Проверка метаданных MusicBrainz
вернула **HTTP 502**. Поэтому все провайдеры не считаются исправными: gateway
обновлён, но доступ MusicBrainz требует повторной штатной проверки. Probe первого
ресурса не подтверждает непрерывное воспроизведение целых треков, seek, длительную
сессию, доступность всего каталога или поведение после смены сети.

## Упаковка, секреты и публикация

Проверены исходники локального сканера staged-файлов, release helper, подготовки
import-tools и macOS workflows. `.gitignore`/`.dockerignore` исключают локальные
секреты, профили и build outputs; Tauri resources указывают на подготовленные
import-tools, без включения файла серверных ключей. Новые загрузки инструментов
проверяются по закреплённому SHA256 до распаковки/использования.

Перед публикацией локальный `audit-staged-release.mjs` проверяет staged-содержимое
по известным точным значениям секретов в памяти и запрещённым путям; сами значения
он не печатает. Его исходники проверены, но результат финального staged-запуска
нужно записать после подготовки релизного commit. Это дополнительная проверка:
она не обнаруживает все неизвестные или перекодированные секреты и не сканирует
автоматически всю историю Git или все готовые пакеты.

Release helper проверяет draft, точный tag, source revision и SHA256 установщиков;
macOS attach сверяет успешный build workflow с ревизией tag и ожидаемыми именами
обеих архитектур. Перед выпуском 0.5.2 версия в helper/путях/asset names должна
соответствовать 0.5.2: прежний helper 0.5.1 сам по себе не выпускает новую версию.
Замена опубликованных assets без проверки не предусмотрена. Фактическая
публикация и подтверждённые hashes новой сборки оформляются отдельно.

Сохранены ограничения цепочки поставки: GitHub Actions пока заданы version tags,
а не immutable commit SHA; Docker images — tags без закреплённых digest.
SHA256 подтверждает совпадение байтов, но не заменяет подпись издателя.
macOS остаётся unsigned preview; проверка на физическом Mac отсутствует.

## Общая проверка и незавершённые сценарии

Результаты на текущем проверенном состоянии исходников:

| Набор | Результат |
|---|---|
| Rust, локальная Windows-цель | 213 прошли, 6 ignored |
| Vitest | 198 прошли |
| Node QA | 316 прошли |
| Gateway, включая реальный локальный Caddy | 78 прошли, 0 skipped |
| Gateway-кандидат в Docker без сети перед развёртыванием | 37 из 37 |
| Native Windows QA с новым IPC guard и автозапуском | 13 из 13 |
| Независимая проверка плавного перехода к треку | 12 из 12 |
| Focused Rust-проверки автозапуска | 6 прошли |
| Независимая UX-проверка автозапуска | 12 из 12 |

Native QA запускалась с отдельным профилем и не подтверждает реальные подписанные
сессии VK/Яндекса/Spotify. Окончательный native-прогон свежей сборки прошёл 13/13: команды автозапуска
доступны через IPC, но QA не регистрируется в системе; исходный порядок и
активная очередь сохранились после настоящего перезапуска процесса.
Физического Mac в этой среде нет; успешная сборка macOS не подтверждает вход,
звук или интеграции на устройстве. Общие функции находятся в одном frontend и
Rust backend для Windows/macOS; Android пока не реализован. Gateway обновлён;
MusicBrainz и полное воспроизведение после развёртывания остаются ограничениями
проверки, описанными выше.
