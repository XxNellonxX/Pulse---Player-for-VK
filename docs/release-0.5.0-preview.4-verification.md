# Pulse 0.5.0-preview.4 — VPS и повторное воспроизведение

23 октября 2026 года. Предварительная сборка для GitHub prerelease, без публикации stable.
Общий код Windows 10/11 и macOS 14+; Android пока не реализован.
`ru.vkplayer.desktop`, прежние папки профиля, настройки и библиотека сохранены.

## Подключение и кеш

- В новых сборках по умолчанию включён `https://pulse-player.duckdns.org`.
  В desktop-пакет попадает только публичный origin. Client Secret остаётся
  на VPS; личные ключи слушателя, системный VPN и настройки прокси не требуются
  для этого маршрута SoundCloud/MusicBrainz. VK использует прямое соединение.
- Общий default JSON, локальный override и переменная сборки применяются
  одинаково на Windows/macOS. Старые EXE/DMG не изменяются задним числом.
- Клиент: RAM-кеш до 128 МиБ аудиосегментов, 1024 записей, 64 stream grants,
  вытеснение давно не использованных записей. Ключ — точный URL и Range.
  Одинаковые одновременные запросы объединяются ограниченными группами блокировок.
- Сервер: отдельный RAM-кеш до 64 МиБ / 128 записей. Доступ ограничен IP,
  capability, треком, подписанным URL и Range. После нового успешного запроса
  SoundCloud можно повторно использовать действующую capability с теми же URL.
  Попадания не продлевают её исходный срок (до 15 минут).
- Сервер сообщает абсолютный и относительный остаток срока. Клиент использует
  монотонные часы и запас 60 секунд, учитывает задержку запроса и неверные часы
  компьютера; локальный предел — 12 минут для managed grant. После истечения
  требуется новое разрешение источника, а новый URL не наследует старые байты.
- Манифесты, ключи шифрования, ошибки и неизвестные бинарные ответы клиент
  не кеширует. 401/403/404/410 сбрасывают доступ; при сетевой ошибке grant
  запрашивается заново. Выход/смена аккаунта или конфигурации очищают клиентский
  кеш. Запоздавшая операция не восстанавливает удалённый кеш.
- Это ускоряет повтор и перемотку внутри действующего сеанса, но не хранит
  всю библиотеку навсегда. [Условия SoundCloud API](https://developers.soundcloud.com/docs/api/terms-of-use)
  допускают только необходимый session-based cache и запрещают постоянные копии.
  Собственные загруженные MP3 Pulse сохраняет отдельно на диске.
- Предварительная загрузка следующего трека не включена: обнаруженный риск
  сброса активного доступа при ошибке фонового источника требует отдельной
  реализации. Отсутствующий prefetch не выдан за готовую функцию.

## Переключение маршрута отдельного трека

Для managed SoundCloud/VPS отсутствие реального продвижения аудио в течение
6 секунд переводит текущую запись на её прямой источник VK с сохранением
позиции. Явный HTTP 401/403/404/500/502/503/504 переключает её сразу. Для 410
сначала допускается одно обновление разрешения той же записи; ожидание также
ограничено. События canplay/playing без движения часов успехом не считаются.

Маршрут меняется только у текущей попытки воспроизведения. Следующий трек
снова использует обычный выбор источника; настройки и системное соединение
не меняются. Пауза, перемотка, смена трека и выход отменяют старые ожидания.
Нет постоянного опроса сервера: один отменяемый таймер и существующие media
events. Прямой маршрут пробует сам VK; его доступность заранее не обещается.
Общий сервер не выключается, личный ключ SoundCloud в клиент не переносится.

## Проверки сервиса и кеша

- Frontend production build, Vitest **86/86**, Node-регрессии **287/287** прошли
  для базового изменения VPS/кеша. Проверки нового переключения маршрута
  фиксируются отдельно ниже после завершения реализации.
- Rust offline: **167 passed, 5 ignored**. Две прежние direct-proxy fixtures
  MusicBrainz теперь явно отключают общий сервис в тестовом объекте, чтобы
  проверять локальный прокси и не обращаться случайно к настоящему VPS.
- Gateway с настоящим Caddy: **72/72**. В том числе независимые проверки
  настоящего HTTP handler: повтор, диапазоны, чужой IP, другой трек, истечение
  во время запроса, ключ, ошибочно использованный как сегмент, и запрет отдавать
  кеш вместо нового отказа провайдера. Синтетический AAC/HLS проходит настоящий
  FFmpeg decoder и перемотку после переписи URL шлюзом.
- VPS обновлён по SSH с проверенным host key; приватный `.env` не заменялся.
  Docker build и **37/37** серверных тестов внутри Node 22 прошли. Gateway после
  рестарта healthy, публичный HTTPS `/healthz` возвращает 200. В одной проверке
  контейнеры использовали 22,2 МиБ (gateway) и 10,52 МиБ (Caddy); это не нагрузочный
  тест, не измерение desktop-памяти и не гарантия её верхнего предела.
- Реальный SoundCloud через VPS: 150 секунд непрерывно декодированы; отдельная
  проверка после обновления декодировала 45 секунд, затем 20 секунд с позиции 90.
  FFmpeg exit 0, все 20 media-запросов 200/206, начало прогресса около 2,4–2,6 с.
  Строгий live harness остаётся failed из-за stderr transport warnings;
  декодирование не выдаётся за полностью чистое прохождение или проверку
  физического звукового выхода, всех записей и всех сетей.
- Настоящий свежий QA EXE с отдельным идентификатором/профилем: **6/6** managed
  IPC/UI проверок. Проверены настроенный маршрут без ключей, гостевой guard,
  отказ неверному custom-protocol URL, очистка сессий, скрытые формы ключей и
  прокси. В пользовательский установленный процесс и профиль тесты не вмешивались.
- Независимые actual React App **14/14** и actual usePlayback **41/41** с
  тестовым IPC/media/MSE прошли. Последние включают 11 новых сценариев:
  таймаут запуска/остановки, сохранение позиции, отсутствие ложного успеха от
  playing/canplay, паузу, смену трека, очистку опоздавшего URL, немедленный
  переход при ошибке, обновление 410 с последующим ограниченным ожиданием и
  возврат обычного выбора для следующей записи.
  Они не доказывают
  реальный VK/SoundCloud stream или работоспособность на физическом Mac.
  Финальные 41 сценарий повторно пройдены в Microsoft Edge; playback harness
  теперь явно использует `channel: 'msedge'`.

## Браузеры и аудиодвижок

В сравнении браузеров Chrome и отдельный Chromium не использовались по просьбе
пользователя. В изолированном
WebView2 самой QA-сборки actual hls.js 1.7.3 декодировал 32-секундный AAC/HLS:
8 секунд → перемотка на 20 → продолжение до 23 → повтор с нуля. Первый прогресс
425 мс, максимальный интервал событий прогресса 268 мс, ошибок HLS/renderer нет.
Чистый Edge 155.0.4283.62 на тех же байтах: 463 мс, 267 мс, перемотка и конец
записи пройдены. Транспорт синтетический и локальный; слышимые микропрерывания
и реальные серверные отказы этим не исключены.

Чистые Edge и официальный Mozilla Firefox 158.0.1 также проверены на реальном
SoundCloud-треке «капля испуга» (#сердцевшрамах, ID 2418736365), через один
managed grant и loopback relay с ограничением origin. 10 секунд → перемотка
к концу → ended на 146,85 с. В финальной общей серии:

| Браузер | Первый прогресс | Макс. интервал прогресса | Задержка перемотки |
| --- | ---: | ---: | ---: |
| Edge 155.0.4283.62 | 1045 мс | 267 мс | 510 мс |
| Firefox 158.0.1 | 1230 мс | 287 мс | 450 мс |

Ошибок decoder/renderer/HTTP нет. Firefox сообщил один нефатальный `aborted`
старого запроса во время перемотки; фаза и событие сохранены в QA-отчёте,
ожидаемая отмена не выдана за сбой декодера. Второй браузер может использовать
серверный кеш первого; это не сравнение скорости двух холодных сетей.
На синтетическом одинаковом AAC/HLS Firefox дал 143 мс до первого прогресса,
290 мс максимального интервала и 28 мс задержки перемотки. Все профили новые,
без пользовательских cookies, кеша и расширений. Это browser-level evidence,
не проверка этой записи через аккаунт и весь нативный транспорт Pulse.
Состояние VPN/системной маршрутизации во время browser-level live проверки
не менялось и независимо не проверялось; работа из любой сети РФ без VPN
по одному этому результату не утверждается.

Две Playwright Firefox-сборки (157 и 142) не запустились из-за Side-by-Side
assembly `mozglue`. Официальный Mozilla Firefox извлечён из установщика
в отдельную QA-папку без установки в систему и успешно проверен через
geckodriver 0.37.1. Ошибка запуска тестовых сборок не объявляется ошибкой Gecko.
Установка Firefox не заменяет Windows backend Tauri:
он использует WebView2. Возможный следующий прототип — отдельный нативный
аудиодвижок при прежнем UI; [сравнение и ограничения](audio-engine-options.md).
Ни libmpv, ни libVLC в эту сборку не включены.

Сценарий `qa/browser-audio-matrix-independent.mjs` запускает синтетическое
сравнение; `--live --query "Капля испуга"` явно включает внешний тест сервиса.
Для официального Firefox указать абсолютные пути в
`PULSE_QA_OFFICIAL_FIREFOX_EXE` и `PULSE_QA_GECKODRIVER_EXE`. Он использует
временный профиль, не устанавливает браузер и не меняет системный default.
Полные локальные отчёты: `release-tauri/browser-audio-matrix-independent.json`
и `release-tauri/browser-audio-matrix-live-independent.json`.

## Платформы и границы проверки

Windows production build и отдельная QA-сборка из общего кода собраны локально.
Локальные артефакты:

- `release-tauri/VK Player_0.5.0-preview.4_x64-setup.exe`: 107 730 822 байта,
  SHA-256 `642a9c05c13f0500afd53d87ff132583f71bd34b43c1cc1169aaa66f63a04db0`.
- `release-tauri/Pulse-Gateway_0.5.0-preview.4.zip`: 42 990 байт, 23 файла,
  SHA-256 `1027d70f3b5108b711303d61272401764d42c08a2f65bacb53c4b9ecf89905bf`.
  Проверен список ZIP: только исходники, тесты, документация и `.env.example`;
  `.env` и пользовательского credential JSON нет.

Production EXE имеет ProductVersion `0.5.0-preview.4`, содержит публичный origin.
Тестовые маркеры `VK_PLAYER_QA_PROFILE`, `VK_PLAYER_QA_FILES`,
`VK_PLAYER_QA_SOUNDCLOUD_FILE` отсутствуют в ASCII и UTF-16. Финальный QA EXE
после frontend-изменений повторно прошёл **6/6** managed IPC/UI проверок.

Установщик поверх пользовательской установки не запускался. Изменения общие
для macOS, но новая macOS arm64/x64 сборка и runtime на физическом Mac в этом
проходе не проверены. Прежние успешные macOS builds не считаются проверкой
этой версии. Stable Release с разными версиями платформ не публиковался.

Кеш ограничен памятью и сроком доступа. Постоянная доступность любого чужого
трека, полная автономность от API и отсутствие всех будущих прерываний
не подтверждены и не обещаются.
