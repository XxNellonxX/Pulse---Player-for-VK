# Pulse 0.4.0 — проверка 21 октября 2026

Windows 10/11 x64, Tauri 2, React и системный WebView2.

Итоговый Windows-установщик: 107 355 491 байт. SHA-256:
`7a2d9419d62d41c0dda69c60d8a36230bc56ffaefba7ce2915bc9677947ec1b3`.
Production-код сборки соответствует коммиту `ce26856`; последующие коммиты
дополняют только QA и документацию.

## Изменения

- Десятиполосный эквалайзер с семью жанровыми пресетами, нейтральным режимом,
  ручной кривой и предусилителем. Настройки сохраняются между запусками.
  Проверка CORS предшествует подключению Web Audio: недоступность обработки
  отображается в интерфейсе, а обычное воспроизведение сохраняется.
- Загруженный MP3 с уже доступной ссылкой VK не застревает в дополнительном
  незавершающемся запросе источника. Восстановление после ошибки продолжает
  запрашивать свежую ссылку, сохраняя позицию и ограничения повторов.
- Импорт прямых публичных файлов и страниц с опубликованным аудио; экстракторы
  SoundCloud, YouTube, Яндекс Музыки, Bandcamp и других поддерживаемых сайтов.
  Поиск другой записи в VK вместо исходника не используется.
- Загрузка в VK MP3, FLAC, WAV, M4A, AAC, OGG, OPUS, AIFF и WebM. MP3 передаётся
  без изменения байтов; другие форматы преобразуются в MP3 320 кбит/с.
  Название и исполнитель сохраняются, результат подтверждается чтением VK.
- Проверка полного декодирования защищает от обрезанного MP3 с сохранившейся
  длительностью в Xing-заголовке. Сравниваются фактическая длительность, данные
  источника и длительность конвертации; неполный файл не считается успехом.
- Колокольчик обновлений рядом с Pulse показывает опубликованный GitHub Release
  и установщик платформы. Перед открытием ссылки сохраняется состояние.
  Установка поверх прежней версии использует прежний идентификатор и профиль.
- Подготовлена сборка macOS 14+ для Apple Silicon и Intel, постоянное хранилище
  сессии WKWebView и отдельные инструменты импорта каждой архитектуры.

## Проверки

TypeScript, production renderer и Vitest: PASS, 13 unit-тестов.
Rust: 88 обычных тестов и четыре отдельные нативные codec-регрессии с настоящими
FFmpeg/FFprobe. Нативные тесты запускаются явно, поскольку требуют этих инструментов.
Изолированные Node-регрессии: 184/184, включая готовый источник своего MP3,
зависший resolver, восстановление, паузу, смену аккаунта и конкурентные запросы.

Независимые проверки эквалайзера:

- PCM-измерения нейтральной кривой, отключения, предусилителя, спектра пресетов,
  запаса уровня, низкой частоты дискретизации и освобождения AudioContext.
- UI при ширине 960 и 1440 во всех 15 темах.
- Нативное сохранение пользовательской кривой, восстановление после перезапуска,
  воспроизведение локального WAV, быстрые переключения пресетов и смена трека.
- Контролируемые CORS-сценарии разрешения и отказа. Отрицательная браузерная
  проверка моделирует отказ запроса; она не доказывает политику каждого CDN VK.

Native codec-регрессии используют настоящие FFmpeg/FFprobe. MP3 с удалённой
половиной байтов отклоняется, хотя ffprobe по заголовку всё ещё показывает полную
длительность. WAV, FLAC, AAC, M4A, OGG, OPUS, AIFF и WebM проверены на подготовку
полного MP3, сохранение тегов, неизменность оригинала и удаление временной копии.
MP3 проходит без перекодирования. Повреждённый файл отклоняется.

Дополнительно сравниваются хеши декодированных PCM-отсчётов при подготовке
локального аудио: AIFF float32, int32, int16, ALAC и AAC. WebM/Opus переносится
в OGG без нового кодирования; допускается только дополнительный хвост менее
миллисекунды из-за округления временной шкалы контейнера, исходные отсчёты
совпадают. Дробный 64-bit WAV не поддерживается WebView2 и отклоняется до
добавления по URL. Это явное ограничение формата, без скрытого снижения точности.

Проверен настоящий публичный MP3 SoundHelix: загрузка по HTTPS, сохранение в
библиотеке, повторный запуск и продвижение времени нативного воспроизведения.
Адреса защищённых сервисов и локальной сети отклоняются без изменения библиотеки.
Сценарий: `qa/import-url-native.mjs`; он использует отдельный временный профиль.

Проверка центра обновлений подтверждает однократный стартовый запрос, безопасный
текст заметок, геометрию окна, повтор после ошибки, Escape и сохранение до открытия
ссылки. Нативный обработчик разрешает ссылки только на VK и релизы этого репозитория.
После публикации `qa/update-center-native.mjs` подтвердил через настоящий Rust
backend версию 0.4.0, опубликованный GitHub Release и правильный адрес Windows EXE.

Независимый нативный набор `qa/tauri-vk-upload-formats-independent.mjs` проверяет
полную цепочку: исходные FLAC/AAC, переданные MP3-байты, чтение порядка VK,
воспроизведение добавленного MP3 при намеренно зависшем resolver сайта и
отказ для повреждённого/обрезанного файла. Реальный аккаунт не изменяется.
Дополнительная проверка нашла и закрыла тот же дефект в выборе локального файла:
обрезанный MP3 теперь отклоняется и там. Повторное добавление подготовленных
AAC/FLAC сохраняет идентификаторы и количество записей; после перезапуска файлы
воспроизводятся. Набор прошёл 6/6 сценариев, базовая нативная загрузка — 5/5.
Отдельный нативный UI-тест подтверждает видимое уведомление с количеством
отклонённых файлов и причиной, а также его закрытие крестиком. Ранее native
отправлял это событие, но интерфейс его не слушал; обработчик теперь подключён.

## Границы подтверждения

Публичная ссылка Spotify не предоставляет этому импортёру полный файл. Spotify,
Apple Music, Deezer и Tidal завершаются понятной ошибкой без скачивания превью и
подмены трека. Доступность SoundCloud, Яндекс Музыки и других сайтов зависит от
конкретной записи, сети и разрешений сервиса. Перечень распознаваемых адресов
не равен доказанной загрузке каждого трека с каждого сайта. DRM не обходится.
В текущей сети проба SoundCloud завершилась таймаутом соединения, а проба
Яндекс Музыки — изменённым ответом API, который закреплённый экстрактор не смог
разобрать. Полный импорт с этих двух сервисов в этой среде не подтверждён.

Когда длительность источника неизвестна, нельзя автоматически доказать, что
сам опубликованный автором файл не является фрагментом. Проверка декодирования
доказывает целостность полученного аудио, а не полноту оригинальной публикации.
Сжатый источник при преобразовании в MP3 не становится качественнее.

Облачные операции тестируются на изолированном runtime сайта, без изменения
реальных треков и плейлистов пользователя. Нет гарантии отсутствия любых будущих
сетевых сбоев, истечения сессии VK или изменений интерфейса сервиса.

macOS требует отдельной проверки на физическом Mac; Windows не подтверждает
поведение WKWebView и аудиокодеков macOS. Проверочные DMG не подписаны и не
прошли Apple notarization. Подробнее: [macos-release.md](macos-release.md).

## Воспроизведение проверок

```powershell
npm run typecheck
npm test
npm run test:rust
node --test qa/*.node.mjs
npm run tauri -- --cargo test media_prepare::tests::native_ -- --ignored --nocapture
npm run tauri -- --cargo test local_audio::tests::native_ -- --ignored --nocapture
npm run tauri -- build --debug --no-bundle --config qa/tauri.config.json
node qa/equalizer-native-independent.mjs
node qa/import-url-native.mjs
node qa/tauri-vk-upload.mjs
node qa/tauri-vk-upload-formats-independent.mjs
npm run dist
```

Нативные сценарии отказываются запускать установленное пользовательское приложение
вместо отдельной QA-сборки. Измерения и данные тестовых профилей в Git не включаются.
