# Подключение общего сервиса Pulse

Состояние на 22 октября 2026 года: пилотный VPS развёрнут, DNS и публичный HTTPS
работают. С разрешения владельца ключи SoundCloud перенесены из локального JSON
по SSH в приватный серверный `.env`; значения не выводились и не включены в Git.
MusicBrainz и поиск SoundCloud отвечают. Выдача аудиопотоков нестабильна (500/503
от SoundCloud), поэтому воспроизведение ещё не подтверждено. Текущий установщик
preview.3 пока сохраняет личный режим; сервер не встроен в него задним числом.

## Требования для первого сервера

Ubuntu 24.04 LTS или Debian 12, Docker Engine и Compose v2. Для пилота выбрать
2 vCPU, 2 ГиБ RAM, 20 ГиБ SSD, публичный IPv4, порт 443 и домен. IPv6 необязателен.
Исходящие HTTPS/DNS должны работать. Желателен тариф с 1 ТБ исходящего трафика
или больше; проверить правила его учёта. При 160 кбит/с один слушатель расходует
около 72 МБ аудио за час плюс накладные расходы. Эти параметры — стартовый
ориентир, не результаты нагрузочного теста и не предел числа слушателей.

Для аренды можно рассматривать VPS в Финляндии, Германии или Нидерландах.
Перед длительной оплатой нужен пробный месяц и проверка именно нужных русских
и зарубежных записей через `probe`, затем полное прослушивание из России.
Страна сервера сама по себе не обеспечивает наличие записи и право её выдачи.
Сравнивать хостеров нужно по доступу к SoundCloud, трафику и оплате, а не только
по объёму RAM. Покупки и подписки автоматически не выполнялись.

Один VPS обслуживает фиксированные API-маршруты SoundCloud и MusicBrainz,
временную передачу разрешённого HLS и TLS. Полная мировая база, отдельная СУБД
и хранилище аудиофайлов не требуются. Кеш метаданных ограничен 32 МиБ/256 записями;
аудио проходит временными ограниченными ответами, не становится публичным архивом.
По умолчанию контейнер шлюза ограничен 384 МиБ, Caddy — 128 МиБ; ОС/Docker и
конкурентная нагрузка требуют дополнительной памяти.

## Что сделать после аренды

1. Направить DNS A своего поддомена, например `music-api.ваш-домен`, на VPS.
2. Перенести [комплект](../services/pulse-gateway/README.md) и выполнить его
   инструкцию установки. Заполнить приватный `.env` прямо на сервере: домен,
   почта, SoundCloud Client ID и Secret, контакт MusicBrainz. В чат ключи не нужны.
3. Запустить тихую проверку Compose, сборку контейнера, проверку Caddy, `up -d`,
   health/ready и probe. Health не подтверждает доступ к провайдерам. Проверить
   несколько конкретных записей целиком, перемотку, паузу более 15 минут,
   смену сети и восстановление после рестарта.
4. После подтверждения работы включить публичный HTTPS-домен в обе платформенные
   сборки Pulse из одной версии исходников. Секрет в EXE/DMG не добавлять.

У обычного слушателя нет полей ключей/прокси в этой сборке. Пользователь видит
SoundCloud через Pulse, параметры выбора источника и кнопку проверки соединения.
VK продолжает подключаться напрямую; библиотека и подписки остаются на устройстве.
Сервер всё равно получает IP, поисковые запросы и идентификаторы запрошенных
записей, необходимые для обслуживания этих запросов. Сессия VK ему не передаётся.

## Адрес в клиентской сборке

Скопировать `config/pulse-service.example.json` в `config/pulse-service.json`:

```json
{
  "gatewayUrl": "https://music-api.ваш-домен"
}
```

Это пример с заменяемым доменом, не действующий адрес. Файл принимает только
`gatewayUrl`; API-ключи в него добавлять нельзя. Нужен публичный HTTPS-origin,
без пути `/v1`, логина, порта, query или фрагмента. Файл исключён из Git.
`npm run dist` и `npm run dist:mac` используют его через общий скрипт Tauri.
Изменение адреса требует пересборки клиента.

Альтернатива для Windows PowerShell:

```powershell
$env:PULSE_GATEWAY_URL = 'https://music-api.ваш-домен'
npm run dist
```

Для macOS/Linux:

```sh
PULSE_GATEWAY_URL=https://music-api.ваш-домен npm run dist:mac
```

В GitHub Actions macOS используется repository variable `PULSE_GATEWAY_URL`.
Установить тот же адрес для Windows и обеих архитектур Mac. Явно пустая переменная
отключает общий маршрут; при отсутствии переменной и файла сохраняется режим
личного подключения. Недоступность настроенного общего сервера не приводит
к скрытому использованию личных ключей или прямому запросу SoundCloud.
При обновлении сохраняются `ru.vkplayer.desktop`, прежние папки, библиотека,
сессия VK и настройки. Личные ключи не удаляются и не выгружаются на сервер.

## Автоматические обновления каталога

Карточки загружаются по запросу. Недавно просмотренные артисты сохраняются
локально; кнопка подписки добавляет их в ленту MusicBrainz. Это отдельная
подписка каталога Pulse, она не изменяет подписки VK/SoundCloud.

Подписки проверяются после 6 часов, просмотренные карточки — после 24 часов
в течение 14 дней. Запуск и восстановление сети будят планировщик. Пока Pulse
открыт, он проверяет расписание раз в минуту без сетевого запроса, если срок
не наступил. Не более 20 артистов обрабатываются за проход; оставшаяся очередь
продолжается через 15 минут. После ошибок пауза растёт от 15 минут до 6 часов.
При offline текущая проверка отменяется. Первый проход создаёт тихую базу;
в ленте показываются последующие обнаружения в каталоге, а не выдуманные анонсы.

Лимиты: 100 сохранённых артистов, из них до 80 подписок; 100 обнаружений в ленте.
У артиста проверяется первая страница 30 release groups и ещё одна вращающаяся
страница вплоть до offset 270, то есть до 300 записей каталога. Один проход —
до 40 страниц релизов и при отсутствии кеша до 20 запросов сведений артистов.
И клиент, и сервер соблюдают интервал MusicBrainz. Фоновая работа не читает всю
мировую базу и не держит неограниченный список в RAM.

Полнота MusicBrainz зависит от наполнения сообщества: начинающего артиста или
будущего релиза может не быть. Дата и ссылки отображаются только при наличии
в источнике. Кнопка поиска в VK позволяет перейти от метаданных к музыке.
Пока приложение закрыто, локальный планировщик не работает. Изменения API
или правил сервисов могут потребовать обновления Pulse; гарантировать вечную
работу интеграции без сопровождения нельзя.
