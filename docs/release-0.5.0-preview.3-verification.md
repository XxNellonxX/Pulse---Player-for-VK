# Pulse 0.5.0-preview.3 — общий сервис и обновления артистов

22 октября 2026 года. Локальная предварительная сборка, без публикации stable.
Общий код Windows 10/11 и macOS 14+; Android не реализован. Идентификатор
`ru.vkplayer.desktop`, папки профиля и формат библиотеки сохранены.
Включены изменения [preview.2](release-0.5.0-preview.2-verification.md).

Дополнение от 22 октября: пилотный Ubuntu 24.04 VPS развёрнут. Linux Docker
build, **26/26** собственных тестов внутри Node 22, тихая проверка Compose и
`caddy validate` прошли. Контейнер шлюза запущен с read-only/tmpfs/лимитами из
Compose, gateway слушает только loopback. DNS и публичный HTTPS проверены с
компьютера пользователя и независимо другим агентом. С разрешения владельца
реальные ключи SoundCloud перенесены по pinned SSH в приватный `.env` (0600),
без вывода значений. Авторизация и поиск SoundCloud, русские/зарубежные поиски
MusicBrainz возвращают 200. Однако выдача `/streams` нестабильна: прямые
контрольные запросы получали 200, 500 `Middleware error` и 503. Финальный probe
после исправлений всё ещё получает 502 на streams; воспроизведение не подтверждено.

## Реализовано

- Серверный комплект Node/Docker/Compose/Caddy для Ubuntu 24.04/Debian 12.
  Ключи SoundCloud остаются только на сервере. MusicBrainz и разрешённый HLS
  используют фиксированные маршруты. Произвольный fetch-прокси отсутствует.
- Публичный HTTPS-origin задаётся при сборке через `PULSE_GATEWAY_URL` или
  строгий `config/pulse-service.json`. Этот файл не принимает API-секреты.
  В managed-режиме личные ключи, импорт и прокси скрыты до первого кадра
  подтверждённого статуса; VK остаётся прямым.
- Подписки и просмотры артистов, фоновый планировщик, локальная лента найденных
  релизов, offline-кеш и ограниченное постраничное обновление. Техническая форма
  подключения убрана из каталога. Лента не выдаёт обнаружение метаданных за
  анонс артиста. [Расписание и пределы](pulse-service-setup.md).
- Истечение серверной media capability сохраняется как `410` до HLS-клиента.
  Клиент обновляет источник той же записи с сохранением позиции, не дожидаясь
  бесполезных повторов старого URL. 30 секунд подтверждённого продвижения
  медиа-часов возвращают бюджет одного восстановления для следующего сбоя;
  перемотка, пауза и повторные ошибки его не возвращают.
- Сервер ограничивает кеш, запросы, параллелизм, размер ответов и реестр
  временных ссылок. Токены обновляются последовательно и переиспользуются.
  HLS сохраняет шифрование; аудиофайлы и подписанные CDN URL не пишутся на диск.
- VPS-проверка выявила ошибку Compose: `tmpfs` с запятыми должен быть одной
  цитированной YAML-строкой. Исправлено и подтверждено настоящим запуском.
- SoundCloud API получает собственный User-Agent Pulse и явный JSON charset,
  документированный URN; media allowlist принимает ограниченную форму
  `/streams/<grant>/hls`. OAuth по-прежнему не отправляется на CDN. На временный
  HTTP 500/502/503/504 допускается ровно один повтор через 500 мс в пределах
  общего таймаута, с тем же токеном. Это не устранило все реальные отказы.
- DNS входит в общий таймаут исходящего запроса; ожидание DNS больше не
  добавляется сверх оставшегося бюджета. Независимые тесты проверяют обе фазы.
  Получение/refresh токена имеет собственный таймаут; общий HTTP handler
  обрывает соединение клиента через 45 секунд. Длительная нагрузка не проверена.
- Проверка probe теперь показывает только безопасный этап/HTTP-код, принимает
  URN, правильно разрешает HLS references и ограничивает чтение. В Caddy
  исключены request-bearing `http.log.error`, TLS/startup сообщения сохранены.

## Проверки

- TypeScript и production frontend build прошли. Vitest: **86/86**;
  Node-регрессии: **286/286** — исходная проверка desktop-артефакта.
  Текущий gateway с настоящим Caddy 2.11.7: **54/54**, включая изолированный
  502 без URI capability в логах и две регрессии общего DNS/socket таймаута.
- Rust offline: **156 passed, 5 ignored**. После финального ужесточения IP-фильтра
  отдельно прошла его регрессия. Ignored: четыре требующих отдельного codec
  окружения сценария и явно внешний MusicBrainz smoke.
- Независимый actual React App с тестовым IPC: **14/14** для managed-настроек,
  подписок, ленты, навигации, offline, гонок старых ответов и событий.
- Независимый настоящий `usePlayback` с тестовыми media/MSE, IPC и виртуальными
  часами: **30/30**, включая 11 сценариев `410`, позиции, здорового прогресса,
  перемотки, паузы, смены трека и устаревшего движка HLS.
- Ранее добавленный сценарий импорта ключей на текущем интерфейсе: **19/19**;
  сценарий поиска/привязки SoundCloud также прошёл. Секреты в тестах фиктивные.
- Реальный Windows QA EXE с отдельным идентификатором/профилем: IPC, импорт
  настоящего WAV, продвижение часов аудио, сохранение библиотеки/позиции и
  явное гостевое состояние VK прошли. Установленное приложение пользователя
  и его профиль не изменялись.
- Нативные SoundCloud/CSP/CORS и неверные JSON: **8/8**, включая 16 неверных
  файлов. Валидные секреты и реальный keyring не читались/не изменялись.
- Память отдельного QA debug дерева процессов: working set **407,98 МиБ**
  после запуска, **424,86 МиБ** после 10 неудачных нативных поисков;
  private **209,61 → 208,39 МиБ**. Пустая библиотека, без аудио, ключей и
  аккаунта. Working set включает общие страницы процессов WebView2. Это не
  измерение release с большой библиотекой и не доказательство верхнего лимита.

Независимый агент нашёл четыре ошибки сервера: сжатый IPv6 Teredo, HLS steering
URI в первом атрибуте, ложный Content-Range и несогласованный предел поисковой
строки. Все исправлены с регрессиями. Аудит native gateway дополнительно
ужесточил UUID, параметры и курсоры, канонические индексы media и общий таймаут.

Основные команды воспроизведения:

```sh
npm run typecheck
npm test
node --test qa/*.node.mjs
npm run test:gateway
node scripts/tauri.mjs --cargo test --offline --lib
node qa/managed-catalog-independent.mjs http://127.0.0.1:5173
```

Для playback harness используется `PULSE_QA_URL=http://127.0.0.1:5173` и
`node qa/soundcloud-playback-independent.mjs`. Нативные сценарии требуют
предварительной сборки с `--debug --config qa/tauri.config.json` и запуска
по одному, чтобы не разделять QA WebView-профиль.

## Что не подтверждено

Длительное аудио через VPS не проверено. Независимый live harness дошёл до
поиска (200) и остановился на streams (502), до декодирования не дошёл.
Заголовки при одной контрольной серии улучшили результат, но повторная серия
с теми же корректными заголовками всё ещё получила 500/503; считать их
единственной установленной причиной нельзя. Соответствие регистрации
SoundCloud проверено по официальной странице, активную Artist Pro подтвердил
владелец. Успешный OAuth/поиск не доказывает стабильную выдачу потоков.

Прямой MusicBrainz на этой машине ранее имел **0/10** успешных запросов. После
развёртывания общий HTTPS-маршрут вернул 200 с массивами артистов для Кишлака,
Kino и Nirvana. Это подтверждает маршрут каталога, но не полноту метаданных.

macOS arm64/x64 этой версии здесь не собраны и не проверены на физическом Mac.
Ранее успешные Mac-сборки других версий не подтверждают совместимость новых
изменений. CI дополнен тем же публичным URL и gateway-тестами; перед выпуском
нужны новые сборки обеих архитектур и реальные login/playback/import/persistence
сценарии. Прежний macOS preview остаётся неподписанным.

До публичного выпуска нужны настоящие provider probes, полное прослушивание
русских и зарубежных записей, seek/пауза больше 15 минут, смена IP, 403/429,
рестарт сервера, проверка установления поверх старой версии и нагрузочный тест.
MusicBrainz не гарантирует всех новичков/анонсов, SoundCloud определяет права,
регион, полноту потоков и общие квоты приложения. Сервер не гарантирует «любой
трек» и не превращает API-доступ в право на перезаливку аудио в VK.
